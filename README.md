# takes

Контроль версий для любых файлов — как GitHub, но для музыки, графики, видео
и всего остального. Всё хранится локально.

Проект — обычная папка. Работаете в ней как обычно (DAW, Photoshop…), а takes
сохраняет версии и синхронизирует их между устройствами. Каждая версия — это
изменение одного файла: у каждой песни своя история и свои ветки (варианты:
акустика, ремикс…).

Весь функционал по пунктам — в [docs/functionality.md](docs/functionality.md).

## Структура

```
crates/
  takes-core/        ядро (библиотека): хранилище, версии, ветки, слияние
  takes-audio/       анализ аудио: волна и громкость (LUFS, EBU R128)
  takes-cli/         консольная утилита `takes` поверх ядра
apps/desktop/        десктоп-приложение (Tauri 2 + React + TypeScript)
  src/               интерфейс
  src-tauri/         Rust-команды поверх ядра, слежение за папкой
  dev/mock.html      интерфейс на фейковых данных, без бэкенда
```

## Десктоп-приложение

```sh
cd apps/desktop
npm install
npm run tauri dev       # запуск в режиме разработки
npm run tauri build     # установщики для текущей ОС
```

Что нужно для сборки:
- **Linux:** `libwebkit2gtk-4.1-dev librsvg2-dev` (для AppImage ещё `patchelf`);
- **Windows 10/11:** Visual Studio Build Tools (C++); WebView2 уже есть в системе;
- **macOS 10.15+:** Xcode Command Line Tools.

`npm run tauri` идёт через [scripts/tauri.mjs](apps/desktop/scripts/tauri.mjs):
он подхватывает `~/.cargo/bin`, если `cargo` нет в PATH, и на Linux убирает
GTK-переменные, которые протекают из терминала VS Code, установленного как
snap (иначе приложение падает с `symbol lookup error`).

### Выпуск версии для всех ОС

Каждую ОС собирает GitHub Actions на своей машине:

- [ci.yml](.github/workflows/ci.yml) — тесты и clippy на Linux, Windows и
  macOS при каждом push и pull request;
- [release.yml](.github/workflows/release.yml) — установщики для Linux
  (.deb, .rpm, .AppImage), Windows (.msi, .exe) и macOS (универсальный .dmg
  для Intel и Apple Silicon), прикреплённые к черновику релиза на GitHub.

```sh
# поднимите "version" в apps/desktop/src-tauri/tauri.conf.json, затем:
git tag v0.1.0
git push origin v0.1.0
```

Без подписи кода Windows покажет предупреждение SmartScreen, а macOS
потребует разрешить запуск в «Конфиденциальность и безопасность». Для подписи
macOS нужен Apple Developer ID — секреты перечислены в release.yml.

### Особенности ОС

- **Занятые файлы.** Windows не даёт заменить файл, открытый в другой
  программе. Перед переключением ветки, слиянием или восстановлением takes
  проверяет все затрагиваемые файлы и, если какой-то занят, ничего не меняет и
  говорит, какой файл закрыть.
- **Форматы в плеере** зависят от движка ОС: WAV и MP3 играют везде; FLAC —
  на Windows, macOS и Linux; OGG — на Windows и Linux (на macOS зависит от
версии Safari); AIFF — только на macOS.
  На Linux нужны плагины GStreamer (`gstreamer1.0-plugins-good`, для mp3 ещё
  `-ugly`).
- **Регистр имён.** На macOS и Windows `Song.wav` и `song.wav` — один файл;
  переименование только регистром видно как удаление и добавление.

Чтобы работать над интерфейсом без Rust, запустите `npm run dev` и откройте
http://localhost:1420/dev/mock.html в браузере.

## Как хранятся данные

```
МойАльбом/
├── 01 Intro.wav           ← обычные файлы
├── .takesignore           ← что не отслеживать (синтаксис .gitignore)
└── .takes/
    ├── objects/ab/cd…     ← куски файлов (FastCDC, BLAKE3, zstd)
    └── db.sqlite          ← версии, ветки, теги, комментарии
```

- **Дедупликация.** Файлы режутся на куски по содержимому (~1–2 МБ). Копия
  файла или правка в середине большого проекта не дублирует неизменённые куски.
- **Версия (snapshot)** — снимок всего проекта: путь → хэш содержимого.
  Ветка — указатель на версию. Слияние трёхстороннее, но по файлам: если файл
  изменён в обеих ветках, вы выбираете `ours`, `theirs` или `both` (второй
  вариант сохраняется рядом как `name (ветка).ext`).
- **Безопасность.** Переключение веток, синхронизация и восстановление никогда
  не затирают несохранённую работу (новые несохранённые файлы просто остаются
  в папке); файлы пишутся атомарно (temp + rename); каждый кусок
  проверяется по хэшу при чтении. Файл, который DAW ещё дописывает, не
  сохранится наполовину: takes заметит, что он меняется, и попросит повторить.
- **Скорость.** Статус читает файл, только если по размеру и времени изменения
  нельзя понять, менялся ли он: пока DAW пишет дорожку, takes её не
  перечитывает. При сохранении версии каждый файл читается один раз.

### Добавление файлов и версии

Файлы и папки добавляются в проект кнопкой «Добавить», перетаскиванием в окно
или из схемы (`takes add` в консоли). Они копируются в папку проекта и сразу
сохраняются — каждый файл отдельной версией, папка тоже разбивается по файлам.
Файл с тем же именем, что уже есть в проекте, становится его новой версией;
«Загрузить новую версию…» у файла принимает файл с любым именем (например,
`Night_final_v7.wav` как новую версию `Ночь/mix.wav`). Несохранённые изменения
при этом никогда не перезаписываются.

### Файлы

Вкладка «Файлы» — все файлы папки проекта с их состоянием: сохранён, изменён,
новый, удалён с диска, переименован. Внизу списка — файлы, удалённые из
проекта (сохранённые как удалённые); их можно вернуть. ↑ и ↓ выбирают файл,
Enter переходит к описанию.

Справа — панель файла. Если он не сохранён, сверху блок «сейчас на диске»:
послушать, сравнить с последней версией, описать изменения и сохранить версию
или отменить изменения. Описание у каждого файла своё и не пропадает при
переключении (и даже после перезапуска), пока файл не сохранён. «Сохранить все»
делает по версии на каждый файл — каждую со своим описанием, а файлы без
описания получают автоматическое («Новая версия «mix.wav»»). Ниже — история
версий файла: слушать, сравнивать с предыдущей или с любой другой
(«Сравнить…»), метки, вернуть, положить копию рядом.

**Переименование.** Файл, переименованный или перемещённый в другую папку (в
файловом менеджере, кнопкой «Переименовать…» или `takes mv`), не теряет
историю: это одна версия «переименован», и история продолжается под новым
именем. Takes узнаёт переименование по содержимому: удалённый и новый файл с
одинаковыми данными — это один файл.

### Схема

Вкладка «Схема» показывает проект как Blueprint: на полотне с сеткой у каждой
песни (файла) своя рамка-дорожка. Слева узел самой песни, от него проводами
идут узлы её версий (Версия 1, Версия 2…) слева направо, каждая ветка трека —
в своём ряду. Метка «в папке» показывает версию, которая сейчас лежит в папке
проекта, а несохранённый файл стоит в конце своей ветки оранжевым узлом
«Сейчас в папке» с кнопкой «Сохранить».

На узлах — прослушивание и сравнение с предыдущей версией, правая кнопка
открывает остальное: положить версию в папку, копию рядом, метки, ветки,
отметить версию. Щелчок по узлу открывает сбоку ту же панель файла, что и во
вкладке «Файлы». Полотно двигается мышью, колесо прокручивает, Ctrl + колесо
меняет масштаб, F показывает всё, Ctrl+F ищет песни, ветки и заметки, в углу —
мини-карта.

Полотно свободное, как в Unreal: любой узел, а за заголовок и всю дорожку
песни, можно поставить куда угодно — провода тянутся следом, всё
выравнивается по сетке. Правой кнопкой по пустому месту добавляются тайлы без
файла: заметка (текст и цвет), заготовка песни (бросьте на неё файл или
выберите его — и она станет песней проекта на том же месте) и рамка, которая
группирует песни и заметки и двигает их вместе с собой. Раскладка и тайлы
хранятся в проекте и одинаковы на всех устройствах; «Упорядочить» снова
раскладывает песни одну под другой.

**Ветки треков.** Ветки есть у каждого трека, а не у проекта: это ряды его
дорожки («основная», «акустика», «ремикс»). Новая ветка начинается с файла с
диска, папка при этом не меняется. Версию можно перетащить на другую ветку
трека (во время перетаскивания сверху появляются его ветки) или выбрать
«Перенести в ветку» в её меню — меняется только то, к какой ветке она
относится. У каждого трека в папке лежит одна ветка; новые сохранения
продолжают её, а «Положить в папку» кладёт туда любую версию любой ветки.
Ветки видны и во вкладке «Файлы»: метка в списке и раздел «Ветки трека» в
панели файла.

### Место на диске

Счётчик «N верс. · X ГБ» в шапке открывает очистку (в консоли —
`takes cleanup`):

- версии удалённых веток, к которым больше ничего не ведёт, удаляются всегда;
- по желанию — файлы промежуточных версий старше месяца, полугода и т. д.
  Версии остаются в истории, но их файлы больше нельзя прослушать или вернуть.
  Всегда сохраняются последние версии веток, отмеченные версии и версии
  с открытыми комментариями.

### Релизы и превью

- **ZIP версии** — «Скачать ZIP» в истории (`takes archive master-v1 album.zip`):
  все файлы версии одним архивом, например чтобы отправить на лейбл.
- **Плеер** показывает громкость (LUFS) и примерные темп и тональность
  («≈128 BPM · Am»), в A/B-сравнении поверх волны виден контур второй версии.
- **Картинки** открываются в приложении, две версии обложки сравниваются
  шторкой.
- **Тексты** (слова песен, заметки, трек-листы) открываются прямо в истории, а
  «Разница» показывает, что поменялось между версиями, с подсветкой изменённых
  слов. Понимает UTF-8, UTF-16 и старые файлы в Windows-1251.
- **PDF** (аккорды, партитуры, договоры) открываются в приложении, две версии —
  рядом.

### Метки, темп и тональность

У любой версии файла можно поставить метки: «демо», «сведение», «мастер»,
«финал» или свои («для лейбла»), и вручную задать темп и тональность, если
автоматическая оценка ошиблась. Метки привязаны к содержимому файла, а не к
версии проекта: сведение с меткой «мастер» остаётся помеченным во всех
следующих версиях, пока его не перезаписали. Метки видны в списке файлов и в
истории и синхронизируются между устройствами (при правке на двух устройствах
побеждает более поздняя).

## Синхронизация

История проекта (не рабочая папка!) синхронизируется через «хранилище» —
любое место, где можно читать и писать файлы:

- **папка** — внутри Google Диска, Dropbox или Яндекс Диска (их приложение
  загрузит её в облако), на NAS или флешке;
- **WebDAV** — Яндекс Диск напрямую (`https://webdav.yandex.ru`, нужен
  пароль приложения), Nextcloud и др.

Кнопка «Синхронизировать» получает версии и комментарии других устройств,
перематывает ветки вперёд и отправляет свои версии. Если ветка изменилась на
двух устройствах, она появляется как `main@Студия` и сливается обычным
диалогом слияния. Несохранённые файлы никогда не перезаписываются.

Приложение синхронизируется и само: при открытии проекта, после сохранения
версии и каждые 5 минут (отключается в настройках). Автоматическая
синхронизация не трогает файлы в папке — пока DAW держит проект открытым,
новая версия с другого устройства ждёт кнопки «Обновить файлы». Ветка,
удалённая на одном устройстве, исчезает и на остальных, если на них в ней
не сохраняли ничего нового.

Устройство формата: файлы в хранилище только добавляются (пакеты чанков по
~64 МБ, версии, комментарии, метки, общие настройки проекта вроде порядка
песен), и каждое устройство пишет лишь свои ссылки на
ветки — поэтому не нужны блокировки, а прерванная отправка докачивается без
повторной загрузки. Запросы идут по несколько сразу, а каждая версия называет
несколько предыдущих, так что длинная история скачивается параллельно, а не
по одной версии. Всё скачанное проверяется по хэшам. Пароли WebDAV хранятся
в системной связке ключей. Подробности — в
[repo/sync.rs](crates/takes-core/src/repo/sync.rs).

```sh
takes remote folder ~/GoogleDrive/Takes/Альбом       # или:
takes remote webdav https://webdav.yandex.ru "Takes/Альбом" --user login
takes sync
takes clone ~/Music/Альбом webdav https://webdav.yandex.ru "Takes/Альбом" --user login
takes merge "main@Студия"                            # если ветки разошлись
```

## Использование

```sh
cargo build --release
alias takes=$PWD/target/release/takes

cd ~/Music/МойАльбом
takes init
takes config user.name "Имя"
takes status
takes commit -m "Первые демки"            # по версии на каждый изменённый файл
takes commit -m "Новый припев" "02 Ночь/mix.wav"
takes add ~/Downloads/Ночь_final.wav ~/Downloads/Stems --to "02 Ночь"

takes switch -c acoustic                  # ветка проекта (в приложении —
takes commit -m "Акустика"                #   ветки у каждого трека)
takes switch main
takes merge acoustic --dry-run
takes merge acoustic --resolve "02 Ночь/mix.wav=both"

takes log                                 # история проекта
takes log --file "01 Intro.wav"           # история одного файла
takes restore "01 Intro.wav" --from HEAD~2 --as "01 Intro (old).wav"
takes mv "01 Intro.wav" "Демо/01 Intro.wav"    # переименовать, сохранив историю
takes export master-v1 "01 Intro.wav" ~/Desktop/intro.wav
takes tag master-v1
takes comment add "01 Intro.wav" "бочка громкая" --at 0:42
takes comment list
takes archive master-v1 ~/Desktop/album.zip  # версия целиком в ZIP
takes label "01 Intro.wav" --add мастер --bpm 128 --key Am
takes diff "02 Ночь/lyrics.txt"              # что поменялось в тексте
takes ls                                     # файлы с метками
takes stats
takes cleanup --older-than 90 --dry-run      # сколько места освободится
```

Версию можно указать как `HEAD`, имя ветки, тег, начало id (`7ec0e8`) и
с отступом назад: `main~2`.
