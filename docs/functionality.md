# Takes: весь функционал

Takes — контроль версий для музыки и любых других файлов. Проект — это
обычная папка, в которой вы работаете как всегда (DAW, редакторы, плееры), а
Takes рядом хранит историю каждого файла, его ветки, метки и комментарии и
синхронизирует всё это между вашими устройствами. Всё хранится локально;
облако нужно только как общая папка для синхронизации.

Документ описывает всё, что умеет программа: понятия, приложение (вкладку за
вкладкой), плеер, синхронизацию, консольную утилиту и то, как устроено
хранение. В конце — что изменилось в последней доработке и что можно сделать
дальше.

## 1. Понятия

| Понятие | Что это |
| --- | --- |
| **Проект** | Папка с файлами и скрытой папкой `.takes` внутри: в ней история версий, база и настройки. |
| **Трек (песня)** | Любой файл проекта: аудио, текст песни, обложка, PDF с аккордами, сессия DAW. У каждого файла своя история. |
| **Версия** | Сохранённое состояние одного файла. Каждое сохранение — отдельная версия своего файла со своим описанием, автором и временем. |
| **Ветка трека** | Отдельная линия версий одного трека: «основная», «акустика», «ремикс». У каждого трека свои ветки, у проекта общих веток нет. |
| **Ветка в папке** | У каждого трека в папке лежит одна ветка. Новые сохранения файла продолжают именно её; любую другую ветку можно положить в папку. |
| **История папки** | Все сохранения проекта по порядку: что и когда менялось в папке. |
| **Метка версии** | Название, навсегда привязанное к сохранению, например «master-v1» или «отправлено на лейбл». |
| **Метки файла** | «демо», «сведение», «мастер», «финал» или свои; ставятся на содержимое файла и видны во всех версиях, где оно не менялось. |
| **Темп и тональность** | Определяются автоматически; можно задать вручную, ручные значения важнее. |
| **Комментарий** | Заметка к версии файла, можно привязать к моменту в треке. |
| **Хранилище** | Общая папка (Google Диск, Dropbox, Яндекс Диск, NAS, флешка) или сервер WebDAV, через которые устройства обмениваются версиями. |
| **Устройство** | Компьютер с копией проекта; у каждого своё имя, видное другим. |

## 2. Приложение

### 2.1. Проекты

Слева — список проектов.

- **＋ → «Папка на этом компьютере…»** — открыть проект. Если в папке ещё нет
  проекта, приложение предложит создать его: файлы остаются на месте, история
  начнёт храниться в `.takes`.
- **＋ → «Получить из хранилища…»** — скачать проект с другого устройства
  через папку или WebDAV в новую пустую папку.
- **×** у проекта — убрать из списка (папка и история остаются на диске).
- Проект, папка которого пропала, показан зачёркнутым с подписью «папка не
  найдена».
- Последний открытый проект запоминается.

### 2.2. Шапка проекта

- **Путь к папке** — щелчок открывает её в файловом менеджере.
- **«N верс. · X ГБ»** — сколько места занимает история; щелчок открывает
  очистку места (раздел 2.8).
- **Имя автора** — от чьего имени сохраняются версии.
- **«Добавить»** — скопировать в проект файлы или папку с другого места.
  Файл с именем уже существующего становится его новой версией. Можно сразу
  сохранить каждый файл отдельной версией с общим описанием.
- **Синхронизация** — кнопка «Синхронизировать» с прогрессом (получаю /
  отправляю N МБ из M), счётчиком неотправленных версий и настройками
  хранилища (раздел 2.9).
- **Перетаскивание файлов в окно** из файлового менеджера — то же, что
  «Добавить». Файл, брошенный на заготовку песни на схеме, превращает её в
  песню (раздел 2.4).

Сообщения под шапкой:

- **«Проект изменился и здесь, и на устройстве X»** — версии разошлись;
  кнопка «Объединить…» открывает объединение (раздел 2.9).
- **«С другого устройства пришли новые версии»** — кнопка «Обновить файлы»
  кладёт их в папку. Если в изменённых файлах есть несохранённая работа,
  приложение просит сначала сохранить или отменить её — работа никогда не
  перезаписывается.
- **«Папка сейчас на старой ветке проекта»** — для проектов из прежних
  версий Takes, где ветки были общими: кнопка возвращает папку на основную
  линию; старые ветки при этом видны как ветки треков.

### 2.3. Вкладка «Файлы»

Все файлы проекта в одном месте.

**Список слева**

- Файлы сгруппированы по папкам и отсортированы по-человечески
  («2. Intro» раньше «10. Outro»); поиск по имени.
- Значок состояния: изменён, новый, удалён с диска, переименован; у
  сохранённых — ничего.
- Ветка трека в папке (если веток больше одной), метки файла, размер.
- Значок карандаша — описание для сохранения уже написано.
- Полоса «Не сохранено: N» с фильтром «только они» и кнопкой **«Сохранить
  все»**: каждый файл станет отдельной версией со своим описанием (у файлов
  без описания — автоматическим: «Новая версия «…»», «Новый файл «…»»).
- Внизу «Удалённые из проекта» — файлы, удаление которых сохранено; их можно
  вернуть.
- Клавиатура: ↑ ↓ — выбрать файл, Enter — перейти к описанию изменений.

**Панель файла справа**

- Имя, папка, состояние, число версий, метки.
- **«Загрузить новую версию…»** — выбрать файл с любым именем (например,
  `Ночь_final_v7.wav`) и сделать его новой версией этого файла.
- **«Переименовать…»** — новое имя или папка; после сохранения история
  остаётся с файлом. Переименование и перемещение файла в других программах
  тоже распознаются: история не теряется.
- **«Показать в папке»**.
- **Несохранённые изменения**: прослушать то, что сейчас на диске, сравнить
  A/B с последней версией, написать описание (сохраняется между запусками,
  пока файл не сохранён), сохранить (Ctrl+Enter), отменить изменения, вернуть
  удалённый файл, вернуть старое имя.
- **Ветки трека**: все ветки с числом версий и пометкой «в папке»; у каждой —
  прослушивание последней версии, сравнение A/B с веткой в папке, «В папку»,
  «Новая версия в ветку…», «Переименовать…», «Перенести все версии в «…»».
  Кнопка «Новая ветка из файла…».
- **Версии файла** — от новой к старой: описание, автор, время, размер,
  ветка, метки файла. У каждой версии:
  - «Сравнить…» — выбрать две любые версии (или версию и файл на диске) и
    сравнить их;
  - A/B — сравнение с предыдущей версией;
  - прослушивание или просмотр;
  - «Метки» — метки файла, темп и тональность этой версии;
  - «Вернуть» — положить файл в папку в этом виде (как несохранённое
    изменение);
  - «Копия» — положить эту версию рядом как `имя (версия).ext`.
  - Версии, содержимое которых удалено очисткой места, остаются в истории с
    пометкой «удалён при очистке».

### 2.4. Вкладка «Схема»

Проект в виде Blueprint, как в Unreal Engine: полотно с сеткой, узлы с
цветными заголовками, пины и провода.

**Что на схеме**

- У каждого трека своя **дорожка** — рамка с названием. Слева узел трека
  (красный заголовок, ромб в цвете песни): число версий, состояние, папка,
  метки, ветка в папке.
- От него проводами идут **узлы версий** (синие): «Версия N», описание, дата,
  автор, метки, теги; кнопки прослушивания и A/B с предыдущей. Слияния —
  фиолетовые, удаления — тёмно-красные, версии не из истории папки — серые.
- **Ветки трека** — ряды дорожки: каждая ветка в своём ряду, ветка в папке —
  первая. Первая версия ветки подписана её названием. Пометка «в папке» — у
  версии, которая сейчас лежит в папке.
- Если файл изменён и не сохранён, в конце его ветки стоит оранжевый узел
  **«Сейчас в папке»** с кнопкой «Сохранить» (с написанным описанием или
  автоматическим); к нему ведёт бегущий пунктир.

**Работа с ветками**

- **Перенос версии между ветками трека**: потащите узел версии — сверху
  появится панель с ветками этого трека и «новая ветка»; бросьте на нужную.
  То же в меню версии: «Перенести в ветку «…»», «Перенести в новую ветку…».
  Перенос меняет только принадлежность версии, файлы не трогаются.
- **Новая ветка из файла** (меню трека, меню версии «Новая ветка от этой
  версии…», панель файла): название и файл с диска, который станет первой
  версией ветки. Папка не меняется, если не отметить «Сразу положить в
  папку».
- **«Положить в папку (ветка «…»)»** в меню версии — файл в папке становится
  этой версией и сохраняется; ветка версии становится веткой в папке, и
  следующие сохранения продолжают её. Несохранённую работу в файле
  приложение не перезапишет.
- **«Новая версия в ветку «…»…»** — файл с диска как следующая версия ветки,
  которая не в папке.

**Свободное полотно**

- Любой узел перетаскивается куда угодно, провода тянутся следом; рамка
  дорожки следует за своими узлами. За заголовок рамки двигается вся песня.
  Всё выравнивается по сетке.
- Раскладка хранится в проекте и одинакова на всех устройствах.
  «Упорядочить» снова раскладывает песни одну под другой (в порядке, в
  котором они стоят сейчас); тайлы остаются на местах.
- **Тайлы без файла** (правая кнопка по пустому месту или «＋ Тайл»):
  - **заметка** — заголовок, текст, цвет; двойной щелчок — редактировать,
    размер меняется за уголок;
  - **заготовка песни** — для песни, которой ещё нет: бросьте на неё файл из
    файлового менеджера или нажмите «Выбрать файл…», и она станет песней
    проекта на том же месте (текст заготовки останется заметкой рядом);
  - **рамка-группа** — например «Disc 1» или «Демки»: всё, что целиком внутри
    неё, двигается вместе с ней.
  - Меню тайла: изменить, цвет, удалить (Delete — удалить выбранный).
- **Поиск** (Ctrl+F): песни по имени и названиям веток, заметки по тексту.
  Найденное подсвечено, остальное приглушено; Enter / Shift+Enter — к
  следующему и предыдущему.
- **Мини-карта** в углу: всё полотно в миниатюре и видимая часть; щелчок или
  перетаскивание переносит туда вид. Кнопка «карта» прячет её.
- Навигация: перетаскивание полотна мышью (или средней кнопкой), колесо —
  прокрутка, Shift + колесо — вбок, Ctrl + колесо или щипок — масштаб, F —
  показать всё, 0 — 100%, + и − — масштаб. Положение и масштаб запоминаются.
- Щелчок по узлу открывает сбоку панель файла (как во вкладке «Файлы»);
  щелчок по пустому месту закрывает её.
- Правая кнопка по узлу — все действия с ним: слушать, сравнить, положить в
  папку, копия рядом, метки, ветки, метка версии, открыть во вкладке
  «Файлы»; по треку — загрузить новую версию, новая ветка из файла,
  переименовать, показать в папке, вернуть удалённый трек.
- «удалённые · N» показывает треки, удалённые из проекта.

### 2.5. Вкладка «История»

История папки — все сохранения проекта по времени.

- Слева лента версий: описание, время, автор, короткий номер, теги и
  пометка «в папке».
- Справа выбранная версия: изменённые в ней файлы с прослушиванием, A/B с
  предыдущим состоянием, «Вернуть» и «Копия».
- **«Отметить версию»** — поставить метку; × на метке снимает её.
- **«Скачать ZIP»** — все файлы этой версии одним архивом (например, для
  лейбла); файлы не пережимаются, так что это быстро.

### 2.6. Плеер и просмотр

**Аудио** (WAV, MP3, FLAC, OGG, Opus, M4A, AAC, AIFF — что умеет система):

- волна с громкостью (пики и RMS), перемотка щелчком;
- громкость LUFS (EBU R128), темп (BPM) и тональность — оценка и ручные
  значения;
- **A/B**: две версии синхронно, переключение без паузы (кнопки или X),
  контур второй версии на волне, **выравнивание громкости** — более громкая
  приглушается до тихой, чтобы сравнивать сведение, а не громкость;
- **повтор фрагмента**: протяните по волне — выделенная часть играет по
  кругу, в A/B тоже; L или × на плашке — перестать;
- **комментарии**: к моменту в треке или ко всей версии, отметки на волне,
  «решено»; комментарии видны во всех версиях с тем же содержимым файла;
- клавиши: пробел — играть/пауза, ← → — на 5 секунд, X — A/B, L — снять
  повтор.

**Картинки** — просмотр и сравнение двух версий шторкой.
**Тексты** (txt, md, lrc, chordpro и др., любые кодировки, включая
Windows-1251) — просмотр и построчная разница между версиями.
**PDF** — просмотр (например, ноты и аккорды).

### 2.7. Метки файлов, темп, тональность

Диалог «Метки, темп, тональность»: готовые метки («демо», «сведение»,
«мастер», «финал»), свои метки, темп 20–400 BPM, тональность. Метки ставятся
на содержимое файла: «мастер» остаётся у файла во всех версиях, пока он не
изменился. Синхронизируются между устройствами.

### 2.8. Очистка места

Окно открывается по счётчику «N верс. · X ГБ».

- Всегда удаляются версии, к которым больше ничего не ведёт.
- По желанию — файлы старых промежуточных версий: старше месяца, трёх
  месяцев, полугода или года. Версии остаются в истории, но без файлов.
- Никогда не трогаются: последняя версия каждой ветки каждого трека,
  отмеченные версии, версии с открытыми комментариями.
- Перед очисткой показано, сколько места освободится.

### 2.9. Синхронизация

- **Хранилище**: папка (облачный диск, синхронизируемый своей программой,
  NAS, флешка) или WebDAV (например, Яндекс Диск с паролем приложения).
  Пароль хранится в системной связке ключей, не в проекте.
- **Имя устройства** — видно на других устройствах.
- **Автосинхронизация**: вскоре после открытия проекта, после сохранения и
  каждые несколько минут. При автосинхронизации файлы в папке не меняются,
  пока вы не нажмёте «Обновить файлы» (DAW может держать их открытыми).
- Передаются версии и их файлы (кусками, без повторов, пачками по 64 МБ),
  комментарии, метки файлов, темп и тональность, общие настройки проекта:
  порядок песен, ветки треков, раскладка схемы, тайлы.
- Если версии изменились и здесь, и на другом устройстве, — **объединение**:
  файлы, изменённые только с одной стороны, применяются сами; для файлов,
  изменённых с обеих сторон, вы выбираете «отсюда», «с устройства» или
  «оставить обе» (вторая ляжет рядом как `имя (устройство).ext`), с
  прослушиванием и A/B прямо в окне.
- Новые несохранённые файлы не мешают получать версии.
- Получить проект на новом устройстве — «Получить из хранилища…».

## 3. Консольная утилита `takes`

| Команда | Что делает |
| --- | --- |
| `takes init [папка]` | создать проект |
| `takes status` | что изменилось с последнего сохранения |
| `takes commit -m "…" [файлы]` | сохранить изменённые файлы, каждый своей версией |
| `takes add <файлы> [--to папка] [-m "…"]` | скопировать файлы в проект и сохранить |
| `takes log [версия] [--file файл] [-n N]` | история проекта или одного файла (с переименованиями) |
| `takes ls [версия]` | файлы версии с метками |
| `takes mv <откуда> <куда>` | переименовать или переместить с сохранением истории |
| `takes restore <файл> [--from версия] [--as путь] [-f]` | вернуть файл из версии |
| `takes export <версия> <файл> <куда>` | достать версию файла, не трогая проект |
| `takes archive <версия> <куда.zip>` | версия целиком в ZIP |
| `takes diff <файл> [--from] [--to]` | разница текстового файла между версиями |
| `takes label <файл> [--add/--remove метка] [--bpm] [--key]` | метки, темп, тональность |
| `takes comment add/list/resolve` | комментарии, `--at 1:23` — к моменту |
| `takes tag [имя] [версия] [-d]` | метки версий |
| `takes branch`, `switch`, `merge` | ветки и слияние на уровне проекта (для опытных; в приложении ветки у каждого трека) |
| `takes remote folder/webdav/remove` | хранилище |
| `takes sync` | синхронизация |
| `takes clone <папка> folder/webdav …` | получить проект из хранилища |
| `takes device [имя]` | имя этого компьютера |
| `takes stats` | сколько места занимает история |
| `takes cleanup [--older-than ДНИ] [--dry-run]` | очистка места |
| `takes config <ключ> [значение]` | настройки, например `user.name` |

Версию можно указать как `HEAD`, тег, начало номера (`7ec0e8`), со
смещением `~N` (`HEAD~2`), а также как `ветка@устройство`.

## 4. Как хранится и почему это надёжно

- **Файлы** режутся на куски по содержимому (FastCDC, около 1 МБ), куски
  именуются по хешу BLAKE3 и сжимаются zstd, если это помогает. Одинаковые
  части разных версий хранятся один раз, поэтому новая версия длинного трека
  с правкой в середине занимает мало места.
- **База** `.takes/db.sqlite` (SQLite, WAL): версии, их файлы, ветки, метки,
  комментарии, кэш хешей файлов в папке (статус не перечитывает гигабайты
  аудио).
- **Запись в папку** атомарная: через временный файл и переименование, так
  что DAW никогда не увидит полфайла. Перед изменением папки проверяется, что
  ни один нужный файл не открыт в другой программе (иначе ничего не
  меняется), и что несохранённая работа не будет перезаписана.
- **Файл, который ещё пишется** (DAW рендерит), не сохраняется: Takes видит,
  что он изменился во время чтения, и просит подождать.
- **Ветки треков, раскладка, порядок песен и тайлы** — общие настройки
  проекта: каждое изменение записывается событием, побеждает последнее;
  устаревшие события удаляются, на хранилище уходит только последнее.
- **Варианты треков вне папки** (новая ветка из файла, версия в ветку не в
  папке) хранятся в истории рядом с основной линией и синхронизируются как
  всё остальное.
- **Хранилище** пишется так, что устройства никогда не перезаписывают файлы
  друг друга: каждое пишет только свои указатели, всё остальное — новые
  файлы с уникальными именами. Скачанные данные проверяются по хешам.

## 5. Последняя доработка

**Исправлено**

- Синхронизация и объединение больше не блокируются новыми несохранёнными
  файлами (раньше 14 новых файлов в папке мешали получить версии).
- При смене хранилища общие настройки (порядок песен, ветки треков, схема)
  не отправлялись в новое — теперь отправляются.
- Очистка места могла удалить файл последней версии ветки трека, которая не
  в папке, — теперь такие версии защищены.
- Метки версий можно было поставить, но не снять — теперь × на метке.

**Убрано и упрощено**

- Ветки проекта в интерфейсе (меню веток, «Новая ветка отсюда» в истории,
  слияние веток) — их заменили ветки треков. Объединение осталось только для
  версий, разошедшихся между устройствами, и называется так.
- Неиспользуемые команды приложения и стили, дублирующийся код обхода папки.

**Оптимизировано**

- Схема строится быстрее на больших проектах: изменения каждой версии
  читаются только из отличающихся строк базы, а не из двух полных списков
  файлов.
- Ветки треков вычисляются один раз на весь проект и общие для вкладок.

**Добавлено**

- Ветки трека во вкладке «Файлы»: метка ветки в списке, раздел «Ветки трека»
  в панели файла (в папку, сравнение A/B с веткой в папке, новая версия,
  переименование, перенос всех версий), ветка у каждой версии.
- Повтор фрагмента в плеере, перемотка стрелками.
- Поиск и мини-карта на схеме.

## 6. Что можно сделать дальше

- **Удаление ветки трека** целиком, с освобождением места от её вариантов
  (сейчас её версии можно перенести в другую ветку).
- **Отмена на схеме** (Ctrl+Z) для перемещений, тайлов и переносов между
  ветками.
- **Альбом подряд**: проиграть все треки по порядку песен с переходами,
  экспорт альбома в ZIP с выбором ветки каждого трека, не трогая папку.
- **Провода от заметок к песням**: привязать заметку или задачу к треку или
  версии.
- **Сравнение двух треков** на схеме: A/B любых двух выделенных узлов.
- Шифрование хранилища, S3/R2, вход через Google; свой сервер со ссылками на
  прослушивание для группы и лейбла.
